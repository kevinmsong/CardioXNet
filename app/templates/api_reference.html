API reference

The server-rendered UI is a thin layer over a JSON API. Everything the UI does is available programmatically under /api/v1. Interactive OpenAPI docs are at /docs (Swagger) and /redoc.

Endpoints

MethodPathDescription
GET/healthLiveness check.
POST/api/v1/genes/validateValidate gene symbols → Entrez IDs.
POST/api/v1/analysis/runStart an analysis; returns an analysis_id.
GET/api/v1/analysis/{id}/statusPoll progress (stage + percentage).
GET/api/v1/analysis/{id}/resultsNormalized results (hypotheses, topology, top genes).
GET/api/v1/analysis/{id}/detailed-resultsFull per-stage pipeline output.
GET/api/v1/analysis/{id}/report/{format}Download report: pdf · markdown · html · json.
GET/api/v1/config/defaultsDefault pipeline configuration.
WS/api/v1/analysis/{id}/progressWebSocket stream of progress messages.

Start an analysis

POST /api/v1/analysis/run
Content-Type: application/json

{
  "seed_genes": ["PIK3R1", "ITGB1", "SRC"],
  "disease_context": "diabetic_cardiomyopathy",
  "config_overrides": {
    "string_neighbor_count": 50,
    "fdr_threshold": 0.05,
    "top_hypotheses_count": 10,
    "pubmed_max_results": 10
  }
}

Response: { "analysis_id": "analysis_…", "status": "started" }. Poll /status until completed, then fetch /results.

Example (curl)

id=$(curl -s localhost:8000/api/v1/analysis/run \
  -H 'content-type: application/json' \
  -d '{"seed_genes":["PIK3R1","ITGB1","SRC"],"disease_context":"diabetic_cardiomyopathy"}' \
  | python -c 'import sys,json;print(json.load(sys.stdin)["analysis_id"])')

curl -s localhost:8000/api/v1/analysis/$id/status
curl -s localhost:8000/api/v1/analysis/$id/results
